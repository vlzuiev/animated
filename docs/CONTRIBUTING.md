# Contributing to Animated

Bug reports and pull requests are welcome. Small fixes can go straight to a pull request; for anything bigger, open an issue first so we can agree on the approach.

One thing to know up front: the lock screen feature relies on macOS behaviour that Apple does not document. It can only be tested on a real Mac, by locking the screen and looking. Please say in your pull request which macOS version you tested on.

## Requirements

- macOS 26 (Tahoe) or macOS 27
- Xcode (the project is currently built with Xcode 27.2)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`
- One Apple aerial wallpaper downloaded in System Settings → Wallpaper. The app borrows its file for the lock screen.

## Build and run

```sh
git clone https://github.com/vlzuiev/animated.git
cd animated
xcodegen generate
xcodebuild -project Animated.xcodeproj -scheme Animated -configuration Debug -derivedDataPath build build
open build/Build/Products/Debug/Animated.app
```

Quit any other copy of Animated first (for example the one in `/Applications`). Two running copies both react to every unlock and get in each other's way.

## Project layout

| Path | What it does |
| --- | --- |
| `project.yml` | The project definition: targets, build settings, version, `Info.plist` values. This is the file to edit. |
| `Sources/AnimatedApp.swift` | The menu bar menu. |
| `Sources/AppDelegate.swift` | Startup, choosing a video, and when the lock screen install runs. |
| `Sources/WallpaperController.swift` | The desktop wallpaper: a video window just below the desktop icons, one per screen. |
| `Sources/LockScreenInstaller.swift` | The lock screen: converts the video, swaps it into the aerial file, selects the aerial, restarts the system renderer. |
| `Sources/LockScreenRefresher.swift` | Listens for lock and unlock, and resets the renderer after each unlock. |
| `Sources/ResourceMonitor.swift` | The CPU, memory and disk figures shown in the menu. |
| `docs/` | This guide, the release process, and the README banner image. |

Two files are generated by `xcodegen generate`, so do not edit them by hand:

- `Animated.xcodeproj` is not in git at all.
- `Sources/Info.plist` is in git, but it is rewritten from `project.yml` on every generate. To change a value, change `project.yml`, regenerate, and commit both.

## How the lock screen works

macOS has no API for a custom animated lock screen. Since macOS 26, Apple's own "aerial" videos are stored in the user's home folder, and macOS plays whichever of them is the selected wallpaper. Animated replaces one of those files with the user's video.

The details below were all found by experiment. Each one looks like something you could simplify, and each one breaks the lock screen if you do.

**The file that gets replaced ("the slot")**

- Location: `~/Library/Application Support/com.apple.wallpaper/aerials/videos/<UUID>.mov`. The app uses the first downloaded aerial it finds.
- Apple's original is copied once to `~/Library/Application Support/Animated/backups/` and never overwritten, so **Use Apple Background** can always put it back.

**What the replacement video must look like**

- A `.mov` file with **no audio track**. With audio, the system shows a black screen.
- At least about three minutes long. The system goes black when a video reaches its end, so short clips are repeated until they are long enough.
- H.264 and HEVC both play, so the app copies the video as it is instead of re-encoding. That takes seconds instead of minutes.

**The still image**

- macOS shows a still before the video starts: `/Library/Caches/Desktop Pictures/<user GeneratedUID>/lockscreen.png`. The app writes the video's first frame there, otherwise the lock screen flashes an old picture.

**The system processes**

- `WallpaperAgent` manages wallpapers. `WallpaperAerialsExtension` is the part that plays aerial videos.
- After a lock session the player can go black on the next lock. The app therefore restarts it right after every unlock.
- It is never restarted while the screen is locked. That blanks the animation the user is looking at.

**What differs between macOS versions**

| | macOS 26 | macOS 27 |
| --- | --- | --- |
| What the "default" wallpaper means | The Tahoe Day aerial, which is the slot | A video on the read-only system volume (`/System/Library/Wallpapers/.default/`), which cannot be replaced |
| Selecting the aerial | Not needed while the wallpaper is "default" | The app rewrites every "default" choice into an explicit selection of the slot aerial |
| After the player is killed | macOS starts it again by itself | macOS does not start it again, so the app restarts `WallpaperAgent` too |

The selection is stored in `~/Library/Application Support/com.apple.wallpaper/Store/Index.plist`. An explicit aerial choice has the provider `com.apple.wallpaper.choice.aerials` and a configuration that is a binary property list `{"assetID": "<slot UUID>"}`. That is exactly what System Settings writes.

Still unknown: whether the restart after unlock is needed at all on macOS 27. If you can show that it is not, removing it there would be a welcome simplification.

Keep version-specific behaviour behind `#available(macOS NN, *)` and leave the path for older versions as it is.

## Debugging

**What is the lock screen actually playing?**

```sh
lsof -c Wallpaper | grep -i '\.mov'
```

A path inside your home folder means the swapped file is in use. A path under `/System/Library/Wallpapers/` means macOS is playing its own video and the aerial is not selected.

**System logs**

```sh
/usr/bin/log show --last 10m --style compact --predicate 'process == "WallpaperAgent" OR process == "WallpaperAerialsExtension"'
```

Use the full path, because zsh has its own `log` command. Useful lines to search for: `Presentation mode did change` (lock and unlock), `extension-proxy` with `ERROR` (the player is gone), and `first video frame enqueued` (playback started).

**Simulating an unlock**

The reset after unlock can be triggered without locking the screen. Save this as `post_unlock.swift` and run `swift post_unlock.swift`:

```swift
import Foundation
DistributedNotificationCenter.default().postNotificationName(
    Notification.Name("com.apple.screenIsUnlocked"), object: nil, userInfo: nil, deliverImmediately: true)
RunLoop.current.run(until: Date().addingTimeInterval(0.5))
```

A few seconds later `pgrep -x WallpaperAerialsExtension` must still print a process ID. A real lock cannot be simulated; for that, press Ctrl+Cmd+Q.

**Starting over**

Menu → **Use Apple Background** restores Apple's video and stops the app's wallpaper.

## Testing checklist

There are no automated tests; the behaviour that matters lives in macOS, not in this code. Before opening a pull request that touches the wallpaper or lock screen code, please go through this list:

1. Choose a video. The desktop animates behind the icons, on every connected screen.
2. Lock with Ctrl+Cmd+Q. The lock screen plays your video.
3. Unlock and lock again. It still plays. Problems often appear only on the second lock.
4. Run the `lsof` command above. It shows the file in your home folder.
5. Choose a different video. The desktop changes at once, the lock screen within a few seconds.
6. Quit and reopen the app. Everything comes back without a prompt.
7. Sleep and wake the Mac. The desktop video keeps playing.
8. **Use Apple Background**. Apple's own video is back on the lock screen.

## Code style

- Swift with no third-party dependencies. Please keep it that way.
- Comments explain why, not what. For anything that works around macOS behaviour, say which macOS version it was observed on.
- Keep changes small and focused, one topic per pull request.

## Commits and pull requests

- Write a short subject that names the change, in the style of the existing history: `README: add banner image`, `macOS 27: keep the lock screen on the user's video`.
- Version bumps are their own commit, `Stamp version X.Y.Z`, and are made by the maintainer as part of a release.
- In the pull request, say what changed, why, and what you tested on which macOS version.
- Contributions are accepted under the project's [MIT license](../LICENSE).

## Reporting a bug

Please include:

- The macOS version (`sw_vers`) and the Animated version.
- What the lock screen shows: your video, Apple's video, a still image, or black.
- Whether it goes wrong on the first lock or only after an unlock.
- The output of the `lsof` command above.
